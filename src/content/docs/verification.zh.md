# CoreNova 验证保证什么

CoreNova Launch 只有在自动化验证全部通过后才发布应用。本页解释这些门禁是什么，
帮助你判断「已验证」在这里意味着什么。

## 发布门禁

只有**全部九项检查**都通过，版本才会发布：

| 检查项 | 证明了什么 |
|--------|-----------|
| Compose 启动 | 应用的 compose 文件拉起了整个栈。 |
| 容器健康 | 容器持续保持运行状态。 |
| 健康检查通过 | 应用的 readiness 端点返回了预期的状态码。 |
| 应用测试 | 预写的行为测试（API + 浏览器）全部通过。 |
| 版本断言 | 运行中的应用报告的版本号与发布版本完全一致。 |
| 截图生成 | 关键场景已截图留证。 |
| 产物发布 | 截图、报告和 Manifest 可从公开存储正常读取。 |
| 平台契约有效 | AWS 部署路径（AMI/CloudFormation/Docker 运行时）已验证且为最新。 |

每条发布记录都锁定了**不可变输入**：应用版本、精确的镜像 tag、镜像 digest（sha256）、
测试套件版本和引用的平台契约。这是结果可复现的基础。

## 「引用」平台是什么意思

应用行为在 CI 容器里验证；AWS 部署路径（基础镜像、CloudFormation、Docker 运行时）
单独验证，频率更低——称为「平台验证」。发布应用引用该平台契约，而不是每次都重跑。
这种拆分让常规发布免于 AWS 费用，同时平台门禁仍是基础设施正确性的唯一真相源。

## 我们不声明什么

GitHub 验证证明的是**应用本身**可以工作，不证明你账号里某台特定 EC2 实例会有
完全一致的表现——那是平台契约覆盖的范围。两者合在一起才构成完整信任链。

## 数据在哪里

站点渲染的所有内容都来自公开存储里的已验证记录（`current.json` 及其历史）。
前端从不推断状态、发布类型或支持区域——逐字展示记录本身。
