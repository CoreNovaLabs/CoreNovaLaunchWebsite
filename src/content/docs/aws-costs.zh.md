# 一次部署要花多少钱

CoreNova Launch 不收取部署服务费。资源运行在你自己的 AWS 账号中，AWS 按实际用量收费；停止使用网站、关闭浏览器或暂停应用上架，都不会停止云资源计费。外部域名、邮件和其他服务可能另收费。

## 默认配置的费用口径

配置与口径核对日期：**2026-09-22**。以下沿用应用注册的估算单价，不是实时 AWS 报价，也不是费用上限。假设：`us-east-1`、Linux 按需实例、每月运行 730 小时、gp3 基础性能、不抵扣免费额度或优惠。

Ghost、Uptime Kuma、n8n 当前注册的默认规格均为 `t3.small`，20 GB 系统盘和 30 GB 数据盘：

| 资源 | 估算口径 | 约每月费用 |
|------|----------|------------|
| t3.small 实例 | $0.0208/小时 × 730 小时 | $15.18 |
| 20 GB gp3 系统盘 | $0.08/GB·月 | $1.60 |
| 30 GB gp3 数据盘 | $0.08/GB·月 | $2.40 |
| 一个公网 IPv4 | $0.005/小时 × 730 小时 | $3.65 |
| **基础资源合计** | 四项相加后取整 | **约 $23/月** |

私有 SSM 访问仍使用带公网 IPv4 的实例，因此不能省略 IPv4 费用。详情页金额及说明来自该版本的验证记录；历史版本或其他应用可能使用不同配置。更改区域、实例或数据卷后，不沿用默认金额。实际单价请在创建前用 [AWS Pricing Calculator](https://calculator.aws/) 核对。

## 不包含哪些费用

- 公网出流量、EBS 快照、CloudWatch 日志存储与写入。
- gp3 超出基础配额的 IOPS 和吞吐量、适用时的 T3 Unlimited 超额 CPU 积分。
- 额外创建的 Elastic IP、备份、DNS、域名、外部邮件或通知服务，以及税费。
- 同时保留新旧两套栈时，两套计算和存储资源的费用。

AWS 免费计划、赠送额度与适用服务取决于账号创建时间及当前政策，不能仅按实例类型判断。请在自己的 Billing 控制台核实，**不要将本例视为免费部署**。建议部署前设置 AWS Budget 告警；告警不是自动关机或硬性费用上限。

## 停止、删栈、删卷分别意味着什么

| 操作 | 数据和费用的变化 |
|------|------------------|
| 停止 EC2 实例 | 按需计算费用停止；系统盘、数据盘和已有快照仍收费。自动分配的公网 IPv4 通常释放；自行分配的 Elastic IP 需另行处理。 |
| 再次启动实例 | 计算重新计费；公网 IP 可能改变，域名 DNS、证书续期和访问需要重新核对。 |
| 删除 CloudFormation 栈 | 实例终止，默认系统盘随实例删除；数据卷设置了 `DeleteOnTermination: false`，保留并继续收费。 |
| 删除保留数据卷 | 卷内数据永久丢失，卷存储计费结束；已创建的快照不会随卷自动删除。 |
| 保留快照或日志 | 仍可能收费，需在对应服务中单独核对和清理。 |

应用目录中的“暂停部署”只限制创建新部署，与停止你账号中的 EC2 实例无关。

## 安全清理步骤

1. **先核对数据。** 阅读[升级与备份](/zh/docs/upgrading-and-backups/)，完成备份，并在隔离环境验证能恢复真实业务数据。数据卷保留不等于备份。
2. **记录资源归属。** 在正确区域打开栈 Outputs，记录 `InstanceId`。在 EC2 实例的 Storage 中记录数据卷 ID、容量和挂载关系；同时记下快照、日志组及自己额外创建的资源。不要仅凭相似名称删卷。
3. **删除栈。** 在 CloudFormation 删除目标栈并确认 `DELETE_COMPLETE`。如遇终止保护或 `DELETE_FAILED`，先查看 Events 并处理明确的阻塞项；不要直接删除不明资源。
4. **检查保留卷。** 到 EC2 → Volumes，用记录的卷 ID 查找。确认该卷没有被其他实例使用，且数据已经恢复验收或明确不再需要，再手动删除。
5. **逐项核对其他资源。** 检查 EBS Snapshots、AWS Backup 恢复点、CloudWatch 日志组以及额外分配的 Elastic IP。只有确认归属和保留需求后才清理。
6. **复查账单。** Billing/Cost Explorer 的数据可能延迟更新；确认没有运行实例和意外保留资源，再观察后续费用。不要把“栈已删除”等同于“账单归零”。

创建失败或回滚也应执行资源核对。重试前先确认旧栈状态和残留资源，避免无意间创建多套持续收费的环境。
